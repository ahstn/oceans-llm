## Advice retained for review

The remaining discussions were assessed, with these decisions:

- Keep the import destination as state. It identifies a pending operation while membership loads. Deriving it from the current selection would move an import when the user switches sets. The deferred-read test proves that the original set receives the tools and that the other draft stays unchanged.
- Keep the route-consumption effects. They preserve the pending import before clearing its URL seed. The callback removes route input; it does not pass fetched data to a parent.
- Keep short, memoized filter/map expressions where both passes are linear. The nested catalog scan was changed because it multiplied server and tool counts. The visibility submenu's linear chain runs only while the menu is mounted.
- Keep cohesive row and cell render branches. Their complexity scores largely count conditional attributes, feature gates, and CSS for one element. The header menu was extracted where it formed an independent workflow; the remaining trigger branches stay together.
- Keep current grid context snapshots. Memoizing the value with recreated rest props would not stabilize it. Omitting labels or callbacks from dependencies could make consumers stale. A broader context redesign needs measured render evidence.
- Keep the existing ReUI helper exports. They are real non-component exports, so the Fast Refresh warning is valid. Moving them changes module imports, while compatibility re-exports retain the warning. This review preserves those boundaries and leaves the development-only advice open.

No React Doctor rules or CI thresholds were weakened. Warning-blocking CI can remain red for these retained advisories. A clean standalone project-wide TypeScript check is not claimed; diagnostics remain outside the changed grid code.
