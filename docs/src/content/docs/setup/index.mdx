Oceans runs as two processes behind one address: the gateway, and the admin UI it proxies at `/admin`. Every setup below runs the same pair. They differ in where the database lives, where secrets come from, and what exists when the gateway first starts.

| Setup | Start with | First sign-in |
| --- | --- | --- |
| Local development | `mise run dev-stack` | `admin@local` / `admin` |
| Production-shaped local | `mise run prod-stack` | `admin@local` with your required bootstrap password, then a new password |
| Docker Compose | `docker compose -f deploy/compose.yaml up -d` | `admin@local` with your password, after one config change |
| Kubernetes with Helm | `helm install` | Only with the bootstrap-admin Job |
| Local process (mise) | `mise run deploy` | `admin@local` with your password, then a new password |

The two local setups build from source and are for trying Oceans or working on it. Local development keeps its data in a libsql file; every other setup uses PostgreSQL. Compose and Helm run the published images from GHCR. The self-hosted setup builds a tagged release from source on a single Linux machine and serves it over Tailscale.
