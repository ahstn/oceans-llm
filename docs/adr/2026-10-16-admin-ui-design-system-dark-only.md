# ADR: Admin UI Design System, Dark Only

- Date: 2026-10-16
- Status: Accepted

## Current state

- [`DESIGN.md`](../../DESIGN.md), the written source for every token and rule
- [`globals.css`](../../crates/admin-ui/web/src/styles/globals.css), where the tokens live
- `/admin/design-system` ([`routes/design-system/`](../../crates/admin-ui/web/src/routes/design-system/)), the living reference
- [`registry.json`](../../registry.json), generated by [`build-shadcn-theme.mjs`](../../scripts/build-shadcn-theme.mjs)

## Context

The admin UI's look had no single source. `globals.css` carried a light palette on `:root` and a dark one on `.dark`, but `<html>` always has `class="dark"`, so the light values never rendered and had drifted unchecked. The blue action color also filled the activity heatmap, the spend trend, ranked meters, and status badges, so actions, data, and state looked alike. `.impeccable/` held a generated description of that old palette for a design tool.

The new palette came from rounds of rendered comparisons on the busiest admin pages: surface families first, then chart palettes, then the action color.

## Decision

### 1. Three color sources, each with one job

- **Surfaces** use Reef: the navy of the account-ready auth art, darkened and kept at about half its chroma so dense data reads on it. Layers run darkest first: frame (`--sidebar`), content panel (`--background`), card (`--card`), and floating layer (`--popover`).
- **Actions** use lilac `#bb9af7` (`--primary`, `--ring`): buttons, links, checked controls, focus, and the active nav icon. Text on lilac is dark (`#040c15`, 8.5:1), because white fails at 2.3:1.
- **Data** uses Tokyo Night colors: five chart series, `--chart-other`, `--chart-hero`, and a five-step `--heatmap-*` ramp. Charts never use the action color.

### 2. Status colors describe state only

Success is Tokyo Night green1 `#73daca`, and warning is `#eaa518`. Destructive is `#fb7185`, Tailwind's rose-400. Status badges always take a status variant (`success`, `warning`, `destructive`, or `secondary`). They never use the default lilac variant, which reads as an action.

### 3. The admin UI is dark only

`<html>` always carries `.dark`, every token lives on `:root` with `color-scheme: dark`, and the UI has no light palette or theme toggle. This change removed the stale light values rather than repairing them. This is a deliberate exception to the shadcn design-system checklist, which expects a working toggle.

### 4. Structure and motion are tokens too

- Cards rest on a floating content panel with a hairline and a faint top highlight. Only floating UI casts a shadow (`shadow-panel`, `shadow-popover`, `shadow-dialog`).
- Duration tokens (`--duration-fast: 120ms`, `--duration-base: 200ms`, `--duration-slow: 320ms`, `--duration-chart: 600ms`) and easings (`ease-standard`, `ease-emphasized`, `ease-exit`) drive one page entrance per navigation, overlay transitions, nav fades, and the chart draw-in.
- All motion stops under `prefers-reduced-motion`. A global CSS reset covers CSS animation and transitions. Charts draw in with JavaScript, so `chartAnimation` sets Recharts' `isAnimationActive: 'auto'`, which skips the draw-in for that preference.

### 5. Every copy is generated from the source or checked against it

`globals.css` is the source.

- `registry.json` and the copies the docs site serves under `docs/public/r` form a shadcn `registry:theme` item, built with a pinned shadcn CLI. `mise run lint` fails when they're stale.
- The docs site's dark theme repeats the admin surfaces, text, lilac, and status colors. `mise run lint` fails when they differ.
- Recharts needs the chart duration as a number, so `src/lib/chart-motion.ts` repeats it. An admin UI test fails when it differs from `--duration-chart`.
- Another admin UI test fails when the design-system page misses an installed component, or a part of one that the app renders, such as a dropdown menu's checkbox item. Parts the admin shell renders count, since the shell frames the page.
- A third fails when a text pair drops below 4.5:1, or a chart series or active heatmap level below 3:1 on the card (WCAG 1.4.11). The design-system page grades the same pairs in the browser.

## Consequences

Benefits:

- A token change in `globals.css` reaches the app, the shadcn package, and the design-system page. Lint and tests fail until the hand-kept copies follow.
- Actions, data, and state no longer share a color, so each can change without blurring the others.
- Every text pair on the design-system page passes WCAG AA, and all but one pass AAA. Every chart series and active heatmap level clears 3:1 on cards.
- Other projects can install the theme with `npx shadcn@latest add ahstn/oceans-llm/oceans-theme`.

Trade-offs:

- The admin UI has no light theme and ignores a light `prefers-color-scheme`. A light theme needs its own palette and contrast checks, not the removed values.
- The docs site keeps a light mode, using Tokyo Night Day roles darkened to pass AA on white. Only its dark values are checked against `globals.css`; the light values are tuned by hand.
- Every admin page changed visually, so the documentation screenshots were retaken.
- Success green sits near the cyan and green chart series, and the blue and purple series are close for colorblind readers. Status badges stay in tables, and charts keep legends and tooltips, so neither relies on color alone.
- Lilac needs dark text. A component that puts white text on `bg-primary` fails contrast.

## Follow-up work

- Derive a light theme: a palette, contrast checks on the design-system page, then a `.dark` split and a toggle. The docs site's light palette is a starting point.
- Decide whether budget and pricing-coverage bars, healthy cache-hit bars, and stat-card icon tiles are data or actions. They use lilac today.
- Give models and harnesses a stable chart color by name instead of by rank.
- Choose a focus style, the sidebar brand mark, and an avatar palette.
- Move team-role and model-capability badges off the default variant.
