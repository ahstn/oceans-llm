The gateway reads one YAML file at startup. It holds structure: providers, models, identities, budgets, and runtime settings. Secrets and deployment-specific values come from environment variables or files through value references. This page explains how the file is loaded, lists every top-level section, and documents the sections that have no page of their own.

## Load and validate the file

The gateway reads the file named by `--config` or the `GATEWAY_CONFIG` environment variable. The default is `./gateway.yaml`. The flag works with every subcommand.

An admin checks a file before deploying it:

```sh
gateway --config ./gateway.yaml config validate
```

`config validate` parses and validates the file, prints a `gateway configuration ... is valid` line, and exits. It fails if the file does not exist.

<Aside type="caution" title="A missing file is not an error at startup">
`gateway serve` and the other commands do not fail when the config file is missing. They start with built-in defaults: a local libSQL database at `./gateway.db`, no providers or models, and a bootstrap admin `admin@local` with the password `admin`. Run `config validate` in your deploy pipeline so a wrong path fails loudly.
</Aside>

Config changes take effect after a gateway restart.

## Top-level sections

Every section is optional. The gateway rejects unknown top-level keys, so a misspelled section name fails startup instead of being ignored.

| Section | What it controls | Reference |
| --- | --- | --- |
| `server` | Listener, log format, OpenTelemetry export, trusted proxies | [`server`](#server) |
| `database` | libSQL or PostgreSQL connection | [`database`](#database) |
| `auth` | Bootstrap admin, OIDC and OAuth sign-in providers | [Auth and access settings](/configuration/access-settings/) |
| `permissions` | Admin UI pages and actions per group | [Auth and access settings](/configuration/access-settings/) |
| `teams`, `users`, `service_accounts` | Declarative identities seeded at startup | [Auth and access settings](/configuration/access-settings/) |
| `budgets` | Inherited user budgets and the budget rejection status | [Budget settings](/configuration/budget-settings/) |
| `budget_alerts` | Budget alert email delivery | [Budget settings](/configuration/budget-settings/) |
| `rate_limits` | Platform rate-limit policies and failure mode | [Rate limits](/configuration/rate-limits/) |
| `providers` | Upstream provider connections and credentials | [Providers](/configuration/providers/) |
| `models` | Gateway models, aliases, and routes | [Models and routes](/configuration/models-and-routes/) |
| `mcp` | MCP OAuth, client OAuth sign-in, registry ownership | [MCP servers](/configuration/mcp-servers/) |
| `skills` | Agent Skills storage (disabled by default) | [Agent Skills](/setup/skills/) |
| `guardrails` | Request and tool-call guardrail packs | [Gateway guardrails](https://docs.oceans-llm.com/operations/gateway-guardrails) |
| `request_logging` | Request-log payload capture and purge | [`request_logging`](#request_logging) |
| `agent_analysis` | Agent session analysis collection and access | [`agent_analysis`](#agent_analysis) |

## Value sources

Fields that hold secrets or deployment values take a reference with a prefix:

| Form | Meaning |
| --- | --- |
| `env.NAME` | The value of environment variable `NAME`. The gateway fails if the variable is not set or is not valid UTF-8. |
| `file./path/to/secret` | The contents of the file, with trailing newlines removed. |
| `literal.value` | The text after `literal.`, used as is. |

Secret fields (for example `database.url`, `auth.bootstrap_admin.password`, OIDC and OAuth `client_secret`, SMTP `password`, and service-account key `value`) accept only these three forms. A plain value without a prefix is rejected with `unsupported secret reference`. So write `url: literal.postgres://...` or `url: env.POSTGRES_URL`, not a bare URL.

Some non-secret fields, such as the GitHub OAuth `client_id` and file paths for provider credentials, also accept a plain value. Each field reference says which form it takes.

Keep secrets in the environment or a mounted secret file. Don't commit them as `literal.` values.

## Minimal local example

This file runs one OpenAI model on a local libSQL database:

```yaml title="gateway.yaml"
server:
  bind: "127.0.0.1:8080"

database:
  kind: libsql
  path: "./var/oceans.db"

auth:
  bootstrap_admin:
    email: "admin@local"
    password: "literal.admin"
    require_password_change: false

providers:
  - id: openai
    type: openai_compat
    base_url: "https://api.openai.com/v1"
    pricing_provider_id: openai
    auth:
      kind: bearer
      token: env.OPENAI_API_KEY

models:
  - id: gpt-4o-mini
    routes:
      - provider: openai
        upstream_model: gpt-4o-mini
```

## Production-shaped example

This file uses PostgreSQL, takes secrets from the environment, forces a password change for the bootstrap admin, and seeds one team, one admin user, and default user budgets:

```yaml title="gateway.yaml"
server:
  bind: "0.0.0.0:8080"
  log_format: json

database:
  kind: postgres
  url: env.POSTGRES_URL

auth:
  bootstrap_admin:
    email: "admin@local"
    password: env.GATEWAY_BOOTSTRAP_ADMIN_PASSWORD
    require_password_change: true

budgets:
  users:
    default:
      cadence: daily
      amount_usd: "70.0000"
      hard_limit: true
      timezone: UTC
    model_defaults:
      - model: gemini-2.0-flash
        budget:
          cadence: daily
          amount_usd: "40.0000"

providers:
  - id: vertex
    type: gcp_vertex
    project_id: env.GCP_PROJECT_ID
    location: global
    auth:
      mode: service_account
      credentials_path: env.GCP_SERVICE_ACCOUNT_JSON

teams:
  - id: platform
    name: Platform

users:
  - name: Platform Admin
    email: ops@example.com
    auth_mode: password
    global_role: platform_admin
    membership:
      team: platform
      role: admin
    budget:
      cadence: monthly
      amount_usd: "100.0000"

models:
  - id: gemini-2.0-flash
    routes:
      - provider: vertex
        upstream_model: google/gemini-2.0-flash
```

The checked-in files show fuller setups: [`gateway.yaml`](https://github.com/ahstn/oceans-llm/blob/main/gateway.yaml) (local demo), [`gateway.prod.yaml`](https://github.com/ahstn/oceans-llm/blob/main/gateway.prod.yaml), [`deploy/config/gateway.yaml`](https://github.com/ahstn/oceans-llm/blob/main/deploy/config/gateway.yaml) (container deploys), and [`deploy/selfhost/gateway.yaml`](https://github.com/ahstn/oceans-llm/blob/main/deploy/selfhost/gateway.yaml) (self-hosting with mise). They are opinionated examples, not the full config space.

## Defaults that matter

If a section is absent, the gateway uses these defaults:

| Field | Default |
| --- | --- |
| `server.bind` | `0.0.0.0:8080` |
| `database.kind` | `libsql` (or `postgres` when `url` is set) |
| `database.path` | `./gateway.db` |
| `auth.bootstrap_admin` | enabled, `admin@local`, password `literal.admin`, no forced password change |
| `request_logging.payloads.capture_mode` | `redacted_payloads` |
| `request_logging.purge.enabled` | `false` |
| `agent_analysis.enabled` | `true` |
| `budgets.exceeded_status_code` | `422` |
| `budget_alerts.email.transport.kind` | `sink` (no email is sent) |

Change the bootstrap admin password before you expose a gateway. [Start up and first access](/setup/first-access/) explains what the bootstrap admin does at startup.

Route defaults (`priority`, `weight`, `enabled`, capability flags) are on [Models and routes](/configuration/models-and-routes/). Permission and budget defaults are on [Auth and access settings](/configuration/access-settings/) and [Budget settings](/configuration/budget-settings/).

## `server`

| Field | Default | Notes |
| --- | --- | --- |
| `bind` | `0.0.0.0:8080` | Must be a socket address such as `127.0.0.1:8080`. The `PORT` environment variable or `gateway serve --port` overrides the port. |
| `log_format` | `pretty` | The checked-in deploy configs use `json`. |
| `otel_endpoint` | unset | OTLP trace endpoint. Must be an absolute `http` or `https` URI with a host. |
| `otel_metrics_endpoint` | unset | OTLP metrics endpoint. Same rule as `otel_endpoint`. |
| `otel_trace_sample_ratio` | `1.0` | `0.0` through `1.0` inclusive. |
| `otel_export_interval_secs` | `30` | Metrics export interval. |
| `trusted_proxies` | `[]` | IP addresses or CIDR ranges. |

The gateway trusts the `X-Forwarded-For` header only when the connection comes from an address in `trusted_proxies`. It uses the resolved client IP for rate limits and admin audit entries. With an empty list, the socket peer is the client. See [Rate limits](/configuration/rate-limits/) for how client IPs affect limits.

For OTLP settings in a deployment, see [Topology and operations](/setup/deploy-and-operations/). For collector and Datadog setup, see [Export traces and metrics](https://docs.oceans-llm.com/operations/observability/export-traces-and-metrics).

## `database`

| Field | Default | Notes |
| --- | --- | --- |
| `kind` | `libsql` | `libsql` or `postgres`. Any other value fails startup. |
| `path` | `./gateway.db` | libSQL or SQLite file. Used only for `libsql`. |
| `url` | unset | PostgreSQL connection URL. A secret field, so use `env.`, `file.` or `literal.`. Required for `postgres`. |
| `max_connections` | `10` | PostgreSQL pool size. |

If `kind` is absent, the gateway uses `postgres` when `url` is set and `libsql` otherwise. Local development uses libSQL with `path`. The production and deploy configs use PostgreSQL with `url: env.POSTGRES_URL`. For migrations and database operations, see [Topology and operations](/setup/deploy-and-operations/).

## `request_logging`

`request_logging.payloads` controls how much of each chat-completion request and response the gateway stores in request logs. `request_logging.purge` controls automatic deletion of old logs.

```yaml
request_logging:
  payloads:
    capture_mode: redacted_payloads
    request_max_bytes: 131072
    response_max_bytes: 65536
    stream_max_events: 128
    redaction_paths: []
  purge:
    enabled: false
    retention: 7d
    schedule: "0 0 * * *"
```

### Payload fields

| Field | Default | Notes |
| --- | --- | --- |
| `capture_mode` | `redacted_payloads` | `disabled` stores no chat-completion request logs. `summary_only` stores summary rows with `has_payload=false` and no payload. `redacted_payloads` stores summaries and sanitised payloads. |
| `request_max_bytes` | `131072` | Budget for the stored request payload, in uncompressed serialised JSON bytes. `1` through `262144`. |
| `response_max_bytes` | `65536` | Budget for the stored response payload. Must be greater than `0`. |
| `stream_max_events` | `128` | Maximum stored stream events. Must be greater than `0`. Usage and error parsing still sees later events. |
| `redaction_paths` | `[]` | Extra paths to redact, added to the built-in redaction. |

A redaction path is a list of object keys separated by dots, anchored at the payload root. `*` matches one whole segment. The gateway rejects malformed paths such as `body..messages` and indexed paths such as `body.messages[0]` at startup.

### Purge fields

| Field | Default | Notes |
| --- | --- | --- |
| `enabled` | `false` | When `true`, the gateway runs a recurring purge worker. |
| `retention` | `7d` | `1d`, `3d` or `7d`. Other values fail startup. |
| `schedule` | `0 0 * * *` | Five-field cron: minute, hour, day of month, month, day of week. Must not run more than once a day. |

Weekday numbers follow the Rust `cron` crate: `1` is Sunday and `7` is Saturday. The Unix value `0` for Sunday is not accepted. Use names (`SUN`, `MON`, and so on) to avoid confusion.

Redaction behaviour, the manual `gateway purge-request-logs` command, and the admin request-log views are on [Observability and request logs](https://docs.oceans-llm.com/operations/observability-and-request-logs).

## `agent_analysis`

`agent_analysis` controls passive analysis of agent sessions, who can see the results, retention, and the scoring inputs. All fields are optional:

```yaml
agent_analysis:
  enabled: true
  shadow_diagnostics_enabled: false
  calibrated_score_enabled: false
  calibration_approval_id: null
  team_admin_enabled: false
  report_retention_days: 90
  queue_retention_days: 7
  context_input_boundary_tokens: 220000
  context_reserved_output_tokens: 128000
  context_penalty_points_per_repeated_excess: 2
  metrics:
    tokens: true
    cache: true
    context: true
    tools: true
    skills: true
    reliability: true
    outcomes: true
    finish_reasons: true
  cache_profiles:
    - provider_key_contains: anthropic
      upstream_model_contains: claude-opus
      minimum_cacheable_tokens: 4096
      default_ttl: five_minutes
```

The values above are the defaults, except `cache_profiles`, which defaults to `[]`. Every metric group is on by default.

| Field | Default | Rule |
| --- | --- | --- |
| `enabled` | `true` | Turns passive collection on or off. |
| `shadow_diagnostics_enabled` | `false` | Shows shadow diagnostics to platform admins. |
| `calibrated_score_enabled` | `false` | Needs `calibration_approval_id`. |
| `calibration_approval_id` | unset | No leading or trailing spaces, at most 256 bytes. |
| `team_admin_enabled` | `false` | Needs `calibrated_score_enabled`. |
| `report_retention_days`, `queue_retention_days` | `90`, `7` | At most `36500`. |
| `context_input_boundary_tokens` | `220000` | Must be greater than `0`. |
| `context_reserved_output_tokens` | `128000` | Must be `0` or more. |
| `context_penalty_points_per_repeated_excess` | `2` | `0` through `255`. |

Each `cache_profiles` entry needs `provider_key_contains`, `upstream_model_contains`, or both, and a `minimum_cacheable_tokens` greater than `0`. `default_ttl` is `five_minutes` (default), `thirty_minutes`, `one_hour` or `unknown`. The gateway places your profiles ahead of its built-in profiles for common Claude and GPT models. Unknown fields anywhere in `agent_analysis` fail startup.

These environment variables override the YAML when set: `AGENT_ANALYSIS_ENABLED`, `AGENT_ANALYSIS_SHADOW_DIAGNOSTICS_ENABLED`, `AGENT_ANALYSIS_CALIBRATED_SCORE_ENABLED`, `AGENT_ANALYSIS_TEAM_ADMIN_ENABLED`, `AGENT_ANALYSIS_CALIBRATION_APPROVAL_ID`, `AGENT_ANALYSIS_REPORT_RETENTION_DAYS` and `AGENT_ANALYSIS_QUEUE_RETENTION_DAYS`. Boolean variables accept `true`/`false`, `1`/`0`, `yes`/`no` and `on`/`off`; any other value fails startup. A retention variable that is not a whole number is ignored. Metric, context and cache-profile settings are YAML only.

After a change to metrics, context or cache profiles, an admin queues retained sessions for analysis again with `gateway recompute-agent-analysis` (`mise run //gateway:recompute-agent-analysis` locally). It processes 100 sessions per run by default, up to 1000 with `--limit`.

For what the analysis shows and who can see it, see [Agent session analysis](https://docs.oceans-llm.com/operations/agent-session-analysis). Team admins also need the `agent_sessions` page in [`permissions`](/configuration/access-settings/).

## Benchmark catalog

The admin Models page shows the Artificial Analysis Intelligence, Coding and Agentic indices for each model. The scores come from a snapshot in the repository, [`crates/gateway-service/data/model_benchmarks.json`](https://github.com/ahstn/oceans-llm/blob/main/crates/gateway-service/data/model_benchmarks.json). The gateway makes no benchmark network calls at runtime and needs no API key.

![Admin Models page with benchmark scores](/images/screenshot-models.png)

By default, the gateway matches scores from the primary route's `upstream_model`. It normalises provider-specific forms such as `us.anthropic.claude-sonnet-4-6-v1:0` or `claude-sonnet-4-6@20260101` to OpenRouter IDs such as `anthropic/claude-sonnet-4.6`, and uses only exact matches. Set `benchmark_model_id` on a model to choose the OpenRouter ID yourself:

```yaml
models:
  - id: scored-model
    benchmark_model_id: anthropic/claude-sonnet-4.6
    routes:
      - provider: bedrock
        upstream_model: us.anthropic.claude-sonnet-4-6
```

`benchmark_model_id` must have the form `publisher/model`, with no spaces and no `:` (so no `:variant` suffix). Other values fail startup. An explicit ID wins over the derived match. An alias uses the nearest `benchmark_model_id` along its alias chain. If the ID is not in the snapshot, the model shows no scores.

Scores change only when a release ships a refreshed snapshot. The attribution to Artificial Analysis, retrieved through OpenRouter, is shown wherever scores appear.

## Validation and limits

The gateway validates the whole file before it starts. A failure stops startup (and `config validate`) with the field name in the error. Validation covers:

- YAML syntax and field types, including enum values.
- Unknown keys at the top level and in `auth`, `permissions`, `budgets`, `agent_analysis`, `models` entries, `teams`, `users` (including `membership`) and `service_accounts`.
- `server`, `database`, `request_logging`, `budget_alerts` and `agent_analysis` rules on this page and on [Budget settings](/configuration/budget-settings/).
- Guardrails, permissions, OIDC and OAuth providers, and MCP settings.
- Provider fields, model and alias references, and route wiring.
- Budget defaults, rate-limit policies, teams, service accounts and users.

<Aside type="note" title="Some sections ignore unknown keys">
Many sections do not reject unknown keys: `server`, `database`, `request_logging`, `budget_alerts`, the entries under `auth.oidc` and `auth.oauth`, route entries under `models[*].routes`, and most provider types. A misspelled field there is ignored and its default applies. Check spelling against the field references.
</Aside>

Some checks happen later. At seed time, the gateway checks that OIDC and OAuth providers referenced by users are enabled, and that a seeded user's auth mode or provider changes only while the user is still invited. At request time, failures come from routing, missing providers, capability mismatches, and missing prices. See [Request lifecycle and failure modes](/reference/request-lifecycle/) for those.
